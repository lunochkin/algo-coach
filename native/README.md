# Climbance (native app)

The engine's client on a phone: the knowledge modules' queues, scheduled
offline. It came from learn, a personal study app, and runs the rules
`docs/architecture/knowledge.md` gives. Fixtures the Python side generates hold
it to that file.

Expo (React Native) and TypeScript, built locally and installed over USB. No
Play Store and no EAS.

## Setup

- Node, Java 21, and the Android SDK at `~/Library/Android/sdk` (or set
  `ANDROID_HOME`).
- `cd native && npm install`.
- Copy `.env.example` to `.env` and set `EXPO_PUBLIC_API_ORIGIN` to the
  engine's address. git ignores `.env`, since the repo is public and the
  address is not.
- Put the signing keys in `signing/`: `release.keystore` and
  `keystore.properties` for release builds, `debug.keystore` for the dev app.
  git ignores the folder. Keep a copy off the laptop: an update signed by
  another key installs only after an uninstall, which drops the records not
  yet synced.

## Signing in

The app opens on Login until it holds a token, with a button per provider. A
button opens Google's or GitHub's sign-in in a browser sheet. The engine
returns to the app through the `climbance://` scheme with a one-time code, and
the app exchanges the code for its token. The token is kept with expo-secure-store and never
logged. Settings holds the engine's address and signs out, which returns the
app to Login.

## The dev app

`just native-dev-apk` installs "Climbance Dev" beside the release app, with a
scheme of its own, `climbancedev://`. The dev app syncs with the local engine,
never with production, so a test answer never reaches the real log.

1. `just app` runs the local engine, and `just seed-module` gives it content.
2. `just native-dev` starts Metro and forwards the phone's ports 8081 and 8000
   to the laptop over USB.
3. In the dev app, Login offers the dev login, which signs in as the user
   `CLIMB_DEV_LOGIN` names.

## Build and install

From the repo root:

```
just native-test      # tsc and vitest, over tests/fixtures/knowledge/scheduling.json
just native-apk       # expo prebuild + gradle assembleRelease, prints the APK path
just native-install   # adb install -r on the connected device
just native-dev-apk   # once: the dev app ("Climbance Dev") next to the release one
just native-dev       # Metro on :8090 with Fast Refresh; the phone reaches it over USB
```

`android/` is generated by `expo prebuild` (CNG) and git-ignored; configure native behaviour in `app.json` or `plugins/`, never by hand.

Signing: release builds use a private key, `signing/release.keystore`, with its passwords in `signing/keystore.properties`. git ignores both. `plugins/with-pinned-keystore.js` copies them into `android/app/` on every prebuild and points the release build at them, and it stops the prebuild if either is missing. Every release build then carries the same signature, so `adb install -r` upgrades in place and keeps local data. Keep a copy of both files off the laptop. Debug builds, the separate `Climbance Dev` app, use the public React Native debug key in `signing/debug.keystore`.

Checks: `npx tsc --noEmit`, `npm test`.

## Architecture

- `packages/core/` (`@climb/core`, at the repository root, shared with the web): pure TypeScript, no React or Expo. Course snapshot loading, FSRS-6 replay (`fsrs.ts`: ts-fsrs's FSRS-6 model, scheduled exactly like the CLI's py-fsrs), status / gating / frontier (`schedule.ts`), the prerequisite graph (`graph.ts`; an invalid one is ignored with a warning in Stats) and its layered layout (`layout.ts`: longest-path columns, barycenter ordering), `next` selection (`select.ts`), queues for next, review and drill (`queue.ts`), exam selection (`modes.ts`), reply handling (`reply.ts`), structured detail checks (`detail.ts`), record formats (`records.ts`). Tested with vitest, including the shared fixtures that the Python test also checks; regenerate them with `uv run --project apps/cli python apps/cli/tests/gen_fixtures.py`.
- `src/lib/`: storage and side effects.
  - `db.ts`: expo-sqlite, in `climb.db`. `attempts`, `sessions`, `statuses`, `focus`, `lessons` and `certs` hold learn's JSON lines, each with the `client_id` minted when it was written and whether it still waits to be sent. `meta` holds settings, the sync cursor and the snapshot's ETag.
  - `courses-cache.ts`: the engine's snapshot, learn's `courses.json` format 6, cached in the document directory.
  - `sync.ts`, `engine.ts`, `auth.ts`: fetch the snapshot when its ETag moved, send the pending records to `POST /api/knowledge/sync`, and keep each record the engine returns that this device does not hold. A record the engine refuses names content it does not hold, so it is not sent again. `auth.ts` runs the sign-in.
  - `notify.ts`: one local notification at the next reminder hour after reviews become available.
  - `store.tsx`: app state; syncs on start, on returning to the foreground, 10 s after each answer and at session end.
- `src/app/`: expo-router screens, react-native-paper with Material You colours. Next, review and drill run as continuous queues (`src/core/queue.ts`): each question is picked when needed from what is ready, unseen ones within the daily new limit (Settings, default 10; 04:00 rollover). Home: the focus line (tap for Practice, Strict toggle, ✕ to clear), Continue with its review/new counts (strict: plus a link to the reviews waiting outside the focus), course cards that open Practice (their frontier line drills that group). Practice (`drill`: course, topic or subtopic, level, kind, only reviews; "+5 new" inside the queue) and Exam (`exam`: fixed sample, feedback and a review of missed questions at the end). Levels form a ladder per subtopic (locks gate new questions only; seen questions in locked groups are still reviewed) and are shown by name (Foundation, Associate, Professional, Expert; short names in table columns); Practice topic rows summarise passed/total per level; subtopics are ordered by graph depth and show what a locked level needs and what they unlock. Details after an answer show Your answer, Diagram, How it works, Example, Pitfalls and Versions (empty ones omitted; diagrams and examples monospace, unwrapped). Lessons (graph format 2; the Lessons screen from the Home app bar lists To read / Read / Locked, and Home shows the next one ready to read) open in a reader that follows in-app `lesson:` links, scrolls to anchors and suggests Next and Related lessons, (react-native-marked; code blocks in the monospace block) with Done and Mark as unread; they reach you as queue items once their pretest is used, from Practice rows, from question Details ("From lesson"), and on the Map as book-shaped nodes (Lessons toggle). Certifications (trophy on Home, also from Stats; certified levels per scope, others shown as practice with passed/total, and "not enough questions yet" when a pool is small): a matrix per course (topics then the course; Foundation to Expert) with coverage/retention rings, a detail sheet with the checklist, Practice links for what is short and "Take exam" when ready; Home shows the next certificate ready for its exam; the Map has a Certifications layer for the derived DAG (`certs.ts` derives everything, mirrored from the CLI). Stats cells open Practice on that group. Map (Home app bar, Stats) draws a course's graph with react-native-svg: columns by depth, level dots coloured covered / open / locked / no questions, dashed offset edges; pan, pinch, Fit; tapping a subtopic highlights its prerequisites and dependents and shows what each level needs, what it unlocks, and a Practice button.
